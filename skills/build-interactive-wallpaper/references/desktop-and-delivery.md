# 桌面与交付

## 字体与任务栏

在目标分辨率和缩放下检查；实际设备不可用时用多个尺寸预览并说明限制。不要只凭浏览器窗口观感确定字号。

- 台词、说话人、回答、作者声明共用字号尺度；用户要求同步放大时不能只改字幕。
- 字号控制持久化并与宿主属性共用状态；放大后检查换行、按钮和面板高度。
- 适当减少过大行间距腾出空间，避免文字挤压和越界。
- 设置按钮/面板保留任务栏安全区并支持滚动，不能仅靠固定 `bottom: 3%`。
- 作者提示按要求显示、自动消失、永久关闭；新增账号后重新检查布局，不将旧作者信息硬编码给新项目。

## 设置交互

设置入口只切本地状态，检查按钮、表单提交、链接和冒泡，避免导航离开壁纸。宿主原生下拉出现问题时按复现情况改普通按钮或可访问选择器，不把某次问题当所有宿主的通病。

用可读背景，必要时避免昂贵实时模糊。检查层叠、pointer events、焦点与 Escape 返回；设置点击不能同时推进剧情。

## 同源打包

沿用现有工程；新建时按当前官方文档核实 Wallpaper Engine 入口、元数据和属性格式，不凭历史版本推定固定 schema。

通常交付可编辑的网页工程目录/完整 ZIP，以及同步的单文件 HTML。视频或静态图按需提供。创建工程不等于已上传创意工坊，发布按用户授权与当前平台流程执行。

1. 核对入口、脚本、CSS、图片、音频和属性，使用相对路径，去除机器专属路径。
2. 建立实际依赖清单，排除调试文件、临时补片、含 UID 的参考、旧输出和无关素材。现有工程优先沿用有效清单，不递归塞进整个工作区。
3. 内联预览前建立统一资源映射，处理 JS 动态路径、CSS url/import、HTML 属性、模块和 fetch；加载脚本前先设置映射。
4. 读取 `renderer.js?v=...` 时去掉查询部分再找本地文件，不把版本参数当文件名。
5. 检查全部依赖；没有 `<script src>` 不代表完全离线，字体、模块和音频仍可能外连。
6. 防止内联脚本中的 HTML 结束标签截断内容；核对 MIME、资源字节及工程/预览最终代码一致。
7. 显示实际运行版本并更新缓存标记；检查完整写入，ZIP 校验 CRC 与解包内容。
8. 核对每个输出保存是否成功，更新原身份，避免同名重复工程。

不要以“上传 ZIP 即可”替代实际导入/发布步骤，确保入口与元数据符合目标平台。

## 验证层级

| 检查 | 能说明 | 不能说明 |
| --- | --- | --- |
| 哈希/清单 | 修改范围与资源增删 | 图像及动作正确 |
| 语法/着色器编译 | 基本可执行性 | 交互、音频和设备体验 |
| 实际着色器离屏渲染 | 被测状态的颜色/几何/合成 | 浏览器布局与桌面兼容 |
| 浏览器播放 | 网页输入、状态、音频和布局 | Wallpaper Engine 宿主兼容 |
| Wallpaper Engine 实机 | 指定设备/版本上的效果 | 所有设备都正常 |

按风险选择充分而有限的检查。优先用真实运行时代码生成蒙版，不用近似实现冒充原结果；近似验证需说明差异。不能启动目标环境时采用可用检查并报告限制，不绕过环境约束。

## 审计脚本边界

`scripts/audit_project.py` 记录可见项目文件的 SHA-256、大小，检查 project.json 入口/预览的本地存在，比较新增/删除/变化；允许列表接受精确相对路径。

跳过隐藏路径、node_modules、__pycache__，拒绝符号链接并限制入口在项目目录内。报告放工程外。脚本不替代依赖分析、图像检查、播放或平台 schema 验证。
